1) what is containerisation ? 
    ** everyone has different OS
    ** steps to run a project vary based on OS
    ** extremely harder to keep track of dependencies as project grows
    ** the way to describe your project configuration in a single file 
    ** it could run in a isolated environment


*** makes life easy when setting up project locally
*** makes it easier to deploy containers 
*** allow for container orchestration which makes deployment breeze


Docker has 3 parts :
    CLI : command line interface
    Engine : where it does the work when you hit the commands 
    Docker Hub : deploy docker images

    docker cli lets you interact with Docker daemon engine 

4) containers vs images ? 
    *** A docker image behaves like a template from which consistent containers can be created.
    If docker was a traditional VM, where image are ISO used to install your VM.
    Images define the initial filesystem state of new containers
    they bundle the source code and dependencies into self contained package thats ready to use with a container runtime

    // containers
        docker ps                           //list of running containers
        docker ps -a                        // all containers
        docker rm <container id or  name>  // remove the docker container
        docker stop <container id or name> // stop the container
        docker container prune              // remove all containers

    // images
        docker images or docker image ls     // show list of images
        docker rmi <image id or name>       // remove the image 
        docker image prune                  // remove all unused images

2) Volumes and Networks 
    **one more use case of docker 
    **docker used to run DBs/ Redis/ Auxillary services 
    **this is useful we dont need to pollute our fs with unneccesary dependencies
    **we bring up and down DBs/ Redis / kafka and clean out our machine

    We want local database to retain info accross restarts (volumes)
    we want to allow docker container to talk to another container (networks)


    Volumes : 
        used for persisting data across starts
        specifically useful for things like databases

    How ? 
        docker volume create volume_database
        docker run -v volume_database:/data/db -p 27017:27017 mongo

        running mongo 
        docker run -p 27017:27017 mongo 

        // it puts you in a bash shell inside container
        docker exec -it contianrId /bin/bash


    Network  :
        docker network create custom_network_name
        docker run -p 3000:3000 --name backend --network custom_network_name <img tag>

        docker run -v volume_database:/data/db --name mongo --network my_custom_network -p 27017:27017 mongo

Multistage builds : 
    Before we have to know : scripts in js , nodemon library

    FROM node:20 AS base 
    WORKDIR usr/src/app
    COPY package*.json .
    RUN npm install

    FROM base AS development        
    COPY . .
    CMD ['nmp', 'run', 'dev']

    FROM base AS production
    COPY . .
    RUN npm prune -production
    CMD ['npm', 'run', 'start']

    // for development and production
    Dev : 
        docker build --target production -t myapp:prod
        docker build --target development -t myapp:dev
    
        docker run  -e MONGO_URI=url -p 3000:3000 -v .:/usr/src/app myapp:dev 

        // -v .:/usr/src/app -> helps us to make changes from our local machine inside the container
